## Where the spec was wrong

**1. Five render states were not exhaustive. There are six.**

`SPEC.md`'s state table bound each state to a `DESIGN-SYSTEM.md` §8 device, but `near_empty` is
defined as `available` **1–2 only**, so `available = 0` in a non-abstain band fell through the
precedence rule entirely. Measured: **92 confident + 332 adjacent combos** render that way — the
market scores above threshold, the user's city stocks nothing. It displayed as `Results for "X"`
over an empty grid, which is *precisely* Groupon's own zero-results screen, the artifact this build
exists to answer.

Found by `fe` while implementing, escalated rather than patched over. Resolved as **SPEC decision
19**: a sixth state, `city_empty`. `near_empty` was deliberately **not** widened to 0–2 — the 1–2
boundary carries `FINDINGS.md` §1's conversion cliff, and a state named "near-empty" firing on zero
would be a lie in a variable name.

**2. The cross-market gap: 2,314 of 3,065 combos have no Part A verdict.**

`query_embeddings` is keyed on `q` alone (613 rows); `query_classes` on `(market, q)` (751). A query
logged in one market and typed in another resolves, abstains, and writes a demand row with
`concept = NULL`. Verified: `search_deals('DE','Berlin','helicopter tour')` returns class, concept
and agreement all null. Fixed by returning `part_a_logged_here`, so the abstain screen prints **no
June figure when there is no row** rather than inferring one from nulls.

**3. `PLAN-TEAM.md` decision 14 was wrong and `be` corrected it.** Flipping the explainer door does
**not** close a rot-flagged hand-maintained string — it re-arms it with a new trigger, from "rewrite
when the screens are built" to "rewrite when O1 lands". A marker comment now says so in the
template. INDEX's defect count did not go down.

## Defects found by the lead that the builders' own checks missed

1. **The staff panel overlaid the page instead of insetting it** — and it opens by default, so six
   elements including the abstain headline ran up to 331px behind it on first load. Only visible by
   rendering the page; both builders had reported the panel complete. Fixed.
2. **Enter did not submit the search.** The submit button's `disabled` prop arrives one Vue render
   behind the keystroke, and per the HTML spec implicit form submission is *silently* skipped when
   the default button is disabled — so clicking worked and Enter did nothing. Free text is a MUST
   and the refusal state has no chip, so the button was its only route. Fixed with an explicit
   keydown handler.

## The independent Codex gate — DEVIATES, and it was right

Run per `CLAUDE.md` after the build reported complete: `codex-interview.sh implement`. **Verdict:
DEVIATES**, two findings, **both confirmed by the lead against the live database** rather than
accepted on the reviewer's word. Both are now fixed.

1. **High — the staff panel stated a falsehood.** `StaffPanel.vue` keyed its demand-row line off
   `band === 'abstain'`, so every `city_empty` response printed *"Not written — not an abstention"*
   while the RPC had just written one. Proven: `city_empty` rows **0 → 1** on a single
   `search_deals('ES','Valencia','limpieza facial')`. Of anywhere in this build for a false claim,
   the "show your working" surface is the worst — and this file asserts the demand loop closes.
   **A lead miss:** the `city_empty` copy and the market-vs-city box were checked at sign-off; that
   line was not re-read against the new state. Fixed and re-verified in the browser: the panel now
   reads *"Written — source=city_empty, automatic"* with the distribution-gap explanation, and
   abstain / confident / adjacent / refusal all report correctly.
2. **Medium — no chip reached `city_empty`.** Criterion 1 requires every state reachable by a named
   chip; the sixth state was reachable only by typing free text with exactly the right market *and*
   city. Correct when the fixture was written — the state did not exist yet. Fixed by deriving a
   `city_empty` chip with an aborting role assertion, like every other role.

**Codex cleared the CUT list explicitly** — no router dependency, no cross-city or travel offer, no
distance claim, no agent, no persona. It independently marked the same things unverifiable that this
file already declares: the `/app` rewrite, the remote error path, and the visual checklist.

**Note on the reviewer harness:** the first `implement` run returned truncated with no VERDICT line.
`codex-interview.sh` keeps `report[:9000]` — it cuts from the **head**, while `codex exec` prints its
session trace *before* the final message, so the verdict is the first thing lost on a long run. It
was re-run with `-o` to capture the final message directly. **A truncated report is an unavailable
reviewer, not a pass.**

**One design question left open deliberately.** `fe` fixed the panel by transcribing the RPC's own
`if v_band = 'abstain' or v_city_empty` condition off the two flags it already returns, rather than
waiting for a dedicated `demand_row_written` field. Its argument, accepted: this reads the RPC's
decision (the `alternatives_above_floor` pattern) rather than inventing one (the bug's actual
cause). **The residual risk is real and stated** — a third write path would reintroduce the same
class of bug, and the dedicated flag is the structural fix.

## What is NOT verified — read this before claiming anything

- **Everything above is local.** The remote (`ewknlggenhrlftdukwme`) is missing migrations **3, 4,
  5 and 6** and carries the old seed with **0 embeddings**. `PLAN-TEAM.md` said "3 and 5"; `be`
  corrected it against `migration list --linked`. **A visitor clicking the green door on the
  deployed site today reaches a backend with no vectors.** Owner task O1.
- **The door's destination is unproven end to end.** `/app#prototype` depends on `vercel.json`'s
  `/app` → `/app.html` rewrite, which cannot be proved locally. Owner task O2, one `curl -I`.
- **The remote-failure path is untested.** On the remote, `search_deals` does not exist, so
  PostgREST returns 404. Whether the error card catches a missing-function 404 as cleanly as a
  network failure has never been exercised. `be` drafted a sentence claiming it would and **cut it**
  as unverified — the right call, and it stays cut here.
- **`live_abstentions` is not a number to assert.** Both lanes clicked the same local database
  during the build, and the lead cleared stray rows between checks. `seed_searches` is immune by
  construction, which is why the per-source recut mattered.
- **`live_abstentions = 0` for GB·London·adrenaline is correct, not broken.** `paintball`'s concept
  is `paintball`, not `adrenaline`, so its live rows land in a different cell than the seeded 222.
- **The explainer's new door has NOT been seen by a human or by a screenshot.** The lead opened the
  regenerated page in a browser and the **top renders correctly**, which is more than O3 had before.
  But the `#demo` section itself was confirmed only through the DOM — the anchor is 22,000px down a
  23,672px document, and screenshot capture returns a blank frame that deep. Computed styles say the
  door is `rgb(1, 124, 31)` with the text "Open the prototype" and the new status paragraph is in
  place; **nobody has looked at it.** O3 stays open.
- **Visual design is reviewed, not measured.** Contrast, hover/focus states and narrow-width
  German/Polish wrapping were checked against `DESIGN-SYSTEM.md` §11 by reading, plus screenshots at
  1280. No systematic contrast measurement was run on the rendered page.
- **`explainer.html` is now 658,949 bytes** in `web/app/dist`. `009-access-gate` criterion 11 still
  records 361,602 — two regenerations stale. Read it at deploy time, never quote it.

## Coordination failure, recorded because it cost work

`be` ran `npx supabase db reset` three times while `fe` was live on the same local database; a
search from `fe`'s process landed 27 seconds before the last one. **The lead had not set a rule at
spawn time** — that is a lead defect, not a builder one. Rule set mid-build: neither lane resets
without asking, and the lead runs coordinated resets. No further loss after that.
